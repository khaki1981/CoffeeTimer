Coffee Timer — UI再設計 提案
コードは未変更です。現状分析（1a）と、デザインシステムを適用した画面構成案（1b〜1f）をまとめました。確認後、画面ごとに段階実装へ進みます。
1a 分析・方針・実装計画
A. 現在のUIの分析
良い点：HTMLがセマンティック（aria-live / aria-expanded / label関連付け）。id設計が明確で、機能ごとにセクションが分離。タイマー数字はすでに最大要素。豆フォームは折りたたみ（details）を導入済み。
課題： ① 画面全体が濃いブラウンで「明るい北欧」と正反対。 ② ▶ ⏸ ■ ♪ の4ボタンが同じ大きさ・同じ強さで、開始が主役に見えない。 ③ 全工程の進捗表示がなく、現在工程がテキスト1行のみ。次の工程が見えない。 ④ PCでは小さなカードが中央に浮くだけで余白が死んでいる。 ⑤ 豆フォームは項目が多く1本の長いスクロールになりがち。折りたたみが閉じていると入力済みか分からない。 ⑥ アイコンがunicodeグリフと絵文字の混在で線の太さが不揃い。
B. 全体のデザイン方針
デザインシステムをそのまま適用します。背景はアイボリー（約70%）、グレージュの窪み・罫線（約20%）、ブラウンはボタン・見出し・重要枠のみ（約8%）、セージ／ブルーグレー／テラコッタは各コンポーネントに1色まで（約2%）。書体は Zen Kaku Gothic New（和文）＋ Outfit（数字・見出し）、タイマー数字は tabular-nums。角丸は入力10px / ボタン14px / カード20px。影は暖色の低い影のみ。木目テクスチャは使わず、ウッドブラウンの「色」で木の温もりを表現。アイコンはLucide線画（1.75px stroke）に統一し、絵文字は☕と⭐のみ残します。
C. 画面構成案（右のモックアップ）
1b スマホ版タイマー（待機中／実行中）・1c PC版タイマー（2カラム）・1d 豆メモ一覧と入力フォーム・1e 音設定・1f メニュー編集。すべてデザインシステムの実コンポーネントで組んでいます。
D. 情報の優先順位
最大：残り時間（Outfit 600・約76px・カード内で唯一の巨大要素）。 2番手：現在の工程（数字の直上、実行中はセージのドット付き）。 3番手：開始ボタン（唯一のブラウン塗り・72px円形。一時停止／停止は52pxの輪郭のみ）。 4番手：工程チップ＋セージの進捗バー、その下に「次：◯◯」。 控えめ：音設定はヘッダー右上の小アイコンへ移動。メニュー選択・豆メモはカード下部、実行中は非表示にして操作を減らします。
E. コンポーネント一覧（既存idとの対応）
・TimerDisplay → #time-display / #current-step / #status-text
・ProgressSteps → 新規追加（進捗表示）
・ControlButton → #start-button 他3つ
・Button → #edit-button / #save-menu-button 他
・Card → .timer-card / 各section
・Select → #timer-preset / #alert-sound 他
・Input → #menu-name / #bean-name 他
・Toggle → #alert-enabled / #bgm-enabled
・Slider → #alert-volume / #bgm-volume

・RatingScale → #bean-rating-controls

F. 実装順序
① CSS変数をデザインシステムのトークンへ差し替え（HTMLは無変更・最も安全） → ② 背景・文字・余白 → ③ タイマーカード → ④ 操作ボタン（▶をLucideへ、サイズ差を付ける） → ⑤ ProgressSteps追加（HTML追記のみ、JSは工程indexを渡す1行） → ⑥ メニュー選択 → ⑦ 音設定パネル → ⑧ 豆メモ一覧（BeanCard化） → ⑨ 豆入力フォーム → ⑩ 折りたたみ（入力済みバッジ） → ⑪ レーダーチャート → ⑫ PC 2カラム（メディアクエリのみ） → ⑬ アニメーション。各段階でタイマー・保存が動作することを確認してから次へ。
G. 変更リスク
・id / name / data属性 / LocalStorageキー / IndexedDB構造は一切変更しません。
・トグル：main.jsが #alert-toggle-label のON/OFF文字を書き換えるため、.toggle-switch の内部構造（input + track + label）は維持が必要。
・折りたたみ：beans.jsが details.open を制御している場合、details/summary要素は残しスタイルのみ変更するのが安全。
・select：カスタム矢印はラッパーspan追加で実現（select自体のidは不変）。
・評価：#bean-rating-acidity 等のhidden inputは維持し、RatingScale UIから値を書き込む。
・進捗表示：main.jsのタイマー処理には触れず、工程切替時に現在indexを反映する表示専用関数を1つ追加。
・PC 2カラムはメディアクエリのみで実現し、DOM順は変えない（スマホ表示への影響ゼロ）。
