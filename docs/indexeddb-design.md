# IndexedDB 設計書

## 目的

Coffee Timer は最初からクラウドサービスを利用せず、

ブラウザ内データベース（IndexedDB）を利用して

ユーザーのデータを保存する。

これにより

* オフラインでも利用可能
* 高速に動作
* ログイン不要
* API料金不要

というシンプルなアプリを目指す。

---

# 開発方針

保存先はすべて

**IndexedDB**

を使用する。

LocalStorage は設定など小さなデータのみ使用可能だが、

メインデータはすべて IndexedDB に保存する。

---

# 保存するデータ

## 1. Brew Menus

抽出レシピ

例

* メニュー1
* メニュー2
* V60
* Kalita

内容

* メニュー名
* 工程一覧
* 蒸らし
* 2投目
* 3投目
* 秒数
* 作成日
* 更新日

---

## 2. Coffee Beans

コーヒー豆メモ

保存内容

* 豆名
* ロースター
* 産地
* 精製方法
* 焙煎度
* 購入日
* 開封日
* 購入価格
* 内容量
* 味評価
* フレーバーノート
* 感想
* 次回試したいこと
* お気に入り

---

## 3. Settings

設定情報

保存内容

* 通知音
* 通知音ON/OFF
* 通知音音量
* BGM
* BGM ON/OFF
* BGM音量
* 最後に選択したメニュー

---

## 4. Brew Logs

抽出履歴

保存内容

* 日時
* 使用した豆
* 使用したレシピ
* 抽出時間
* BGM
* メモ

将来的に

「よく使うレシピ」

などの分析にも利用する。

---

CoffeeTimerDB


---

# 保存タイミング

基本的に

「保存ボタン」

を押したタイミングで保存する。

設定画面は変更時に自動保存する。

---

# データ更新

編集画面から

* 更新
* 削除

ができる。

削除時は確認ダイアログを表示する。

---

# バージョン管理

IndexedDB のバージョンを管理する。

例

Version 1

* brewMenus
* settings

Version 2

* beans

Version 3

* brewLogs

今後機能追加してもデータを失わない設計とする。

---

# 将来のSupabase対応

IndexedDB は

**ローカルキャッシュ**

として利用する。

Supabase を導入した場合は

```
Supabase

↓

同期

↓

IndexedDB
```

という構成にする。

アプリは基本的に

IndexedDB

から読み込む。

ネット接続時のみ

Supabase

と同期する。

これにより

* オフライン利用
* 高速表示
* クラウド同期

を両立する。
